Order of checks on a left-button press (all in `src/modules/PianoRoll/PianoRollEditorWidget.hpp`):

1. **`onButton`** (1624) sees a left press and calls **`beginDrag(e.pos, e.mods)`** (1889). That calls `zoneAt`, and for `ZONE_GRID` it hands off to **`beginGridDrag(position, shift)`** (2032), where the order of checks is written as a lettered A–F chain.
2. Before any edge test, `beginGridDrag` works out `index = noteIndexAt(step, pitch)` (1406, a half-open `[start, end)` step test) and `in_box` from `selectionBounds` (1455). Shift (A) and a press inside a 2+-note selection box (B → `beginMove`/`beginMoveSelection`) both return early, so a note inside a group selection can't be resized.
3. **C, edge grab:** `edgeGrabAt(position, grab)` (1422). On a hit it sets `drag_mode = DRAG_RESIZE`, and `drag_left_edge = grab.left_edge` picks left or right. **D, move:** only if no edge was hit, `index >= 0` leads to `selectOnly` + `beginMove`. E (dismiss the box) and F (paint a new note) come after that.
4. **The grab zone** is computed inside `edgeGrabAt`, which scans notes topmost-first and only looks at the pitch under the pointer. The size is `zone = min(EDGE_GRAB_W, max(1, (x1 - x0)/3))` (1439). It's measured in pixels from `xOfStep`, and `EDGE_GRAB_W` is 4 px (`PianoRollGeometry.hpp:127`). So the zone is a third of the note's width, at least 1 px and at most 4 px. Shrinking it for short notes keeps the edge zones from covering the whole note, so the body stays grabbable for a move.
5. **The right edge is tested first:** `|x - x1| <= zone` (1441). It wins any overlap and has no width condition. The pixel test matters because `noteIndexAt` treats the end step as outside the note.
6. **Why the left edge of a short note can't be grabbed:** the left test (1445) also requires `(x1 - x0) > EDGE_GRAB_MIN_NOTE_W`, which is `EDGE_GRAB_W * 2.5` = 10 px (`PianoRollGeometry.hpp:128`). The comment says this prevents a left grab being confused with a right grab. For a note 10 px wide or less, a press near its start fails C and falls through to D, so it moves the note instead.
7. The hover cursor in `onHover` (1593–1601) runs the same order (box → `edgeGrabAt` → `noteIndexAt` → empty space), so the resize cursor appears exactly where a press would resize.
