Pressing the button runs a fixed check order: shift first, then the selection box, then the edges (right before left), then the note body. The left edge also needs the note to be more than 10 px wide.

1. **Entry:** `onButton` (`src/modules/PianoRoll/PianoRollEditorWidget.hpp:1624`) handles a left press by calling `beginDrag` (:1890). That calls `zoneAt` (:1387), and for `ZONE_GRID` it calls `beginGridDrag` (:2032).
2. **Order inside `beginGridDrag`:** it first computes `noteIndexAt(step, pitch)` (:1405) and `selectionBounds` (:1455). Then it checks, in order:
   - (A) shift changes which notes are selected;
   - (B) a press inside a multi-note selection box always moves the group, so edges are never tested there (:2060);
   - (C) `edgeGrabAt` (:2075) sets up `DRAG_RESIZE` with `drag_left_edge = grab.left_edge`;
   - (D) the note body selects only that note and calls `beginMove` (:2093);
   - (E)/(F) empty space clears the selection or paints a new note.
3. **Grab zone:** `edgeGrabAt` (:1422) checks only notes on the active track at the pointer's pitch, newest first. It tests in pixels, not steps: `zone = min(EDGE_GRAB_W, max(1, (x1-x0)/3))` (:1439). With `EDGE_GRAB_W = 4` (`src/modules/PianoRoll/PianoRollGeometry.hpp:126`), notes 12 px or wider get ±4 px, notes 3–12 px get a third of their width, and narrower notes get ±1 px. The zone shrinks so that a fixed zone can't cover a narrow note completely and make it impossible to move.
4. **Right before left:** for each note, the right edge `|x − x1| ≤ zone` is tested first and returns at once (:1441). The zone reaches past the note's end, which matters because `noteIndexAt` uses a half-open span that doesn't include the end step (comment at :1400–1404).
5. **Why short notes have no left grab:** the left test (:1445) also requires `(x1−x0) > EDGE_GRAB_MIN_NOTE_W`, which is `EDGE_GRAB_W * 2.5 = 10 px` (`PianoRollGeometry.hpp:127`). A note 10 px or narrower can only be resized from the right; a press near its left end falls through to (D) and moves it. The comment's stated reason is that grabbing the left edge must not be confusable with grabbing the right one.
6. **Hover cursor:** `onHover` (:1590–1601) runs the same order (box → `edgeGrabAt` → `noteIndexAt` → crosshair), so the cursor previews what a press will do. It can't see modifier keys, so the shift case isn't shown.
