All references are to `src/modules/PianoRoll/PianoRollEditorWidget.hpp` unless noted otherwise.

1. **Dispatch.** A left press goes `onButton` (1624) → `beginDrag` (1889). `beginDrag` calls `zoneAt` (1387), and for `ZONE_GRID` it passes the press on to `beginGridDrag` (2032).
2. **Order in `beginGridDrag`** (2046–2100). The checks run in sequence and the first match wins:
   - **A. Shift held:** toggles the note's selection, or starts a marquee.
   - **B. Inside the selection box** (`selectionBounds`, 1455; the box only exists with 2+ selected notes): the press moves the group. Edges are never tested here, so a note inside a group can't be resized.
   - **C. `edgeGrabAt` hit:** starts `DRAG_RESIZE`, with `drag_left_edge = grab.left_edge`.
   - **D. `noteIndexAt` hit** (1406): selects only that note and calls `beginMove`.
   - **E/F. Empty space:** dismisses the selection box if one is up, otherwise paints a new note.
3. **Hover cursor.** `onHover` (1590–1602) checks the same things in the same order (box, edge, body, empty) to pick the cursor. It can't see modifier keys, so a shift-press can act differently from what the cursor shows.
4. **Grab zone.** It is computed in `edgeGrabAt` (1422–1451), which scans notes at the pointer's pitch from last to first. Line 1439 sets `zone = min(EDGE_GRAB_W, max(1, width/3))`, where `width = x1 − x0` in pixels.
   - `EDGE_GRAB_W` is 4 px and `EDGE_GRAB_MIN_NOTE_W` is 10 px (`PianoRollGeometry.hpp:127-128`).
   - So the zone is 4 px for notes 12 px or wider, shrinks to width/3 below that, and never drops under 1 px. The comment says this stops a fixed zone from covering a narrow note entirely, which would make it impossible to move.
5. **Right before left.** The right edge is tested first (1441: `|x − x1| ≤ zone` → right resize). The zone spans both sides of the edge, so it reaches pixels just past the note's end. `noteIndexAt` treats a note as a half-open span, so those pixels don't count as part of the note; the edge grab is the only thing that makes the right edge reachable (comment at 1401–1404).
6. **Why a short note's left edge can't be grabbed.** Line 1445 also requires `width > EDGE_GRAB_MIN_NOTE_W` (10 px), so the left edge simply doesn't exist on notes 10 px wide or narrower. The comment says this keeps a left-edge grab from being confused with a right-edge grab. A press there falls through to step D and moves the note.
