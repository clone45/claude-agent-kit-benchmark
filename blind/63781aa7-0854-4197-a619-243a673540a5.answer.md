The wrap width is set in `HelpFormatter.__init__` (`src/click/formatting.py:128-142`) and is stored as `self.width`.

- **Default:** `max_width` defaults to 80 (lines 134-135). If no `width` is passed, it uses `width = max(min(shutil.get_terminal_size().columns, max_width) - 2, 50)` (line 141). So with the defaults, help wraps at 78 columns at most.
- **Terminal size:** `shutil.get_terminal_size().columns` is used, but capped at `max_width`. The result is minus 2 and never less than **50** (the minimum), even on a very narrow terminal.
- **Test override:** the module-level `FORCED_WIDTH` (line 11) is checked before the terminal size (line 139). `CliRunner.isolation` in `src/click/testing.py:438-439` sets it to 80 and restores it at line 593.
- **Explicit width:** if `width` is passed, it's used as-is. The `max_width` cap, the minus 2 and the 50 minimum are all skipped.
- **Context hookup:** `Context.make_formatter` (`src/click/core.py:664-676`) passes `width=self.terminal_width, max_width=self.max_content_width`. `Command.get_help` calls it at line 1268.
- **Context override:** `Context.__init__` takes `terminal_width` and `max_content_width` (core.py:378-379; documented at 265-275). Each is inherited from the parent context if not given (lines 438-449).
- **Command override:** pass `context_settings={"terminal_width": ..., "max_content_width": ...}`. `Command.make_context` (core.py:1386-1388) copies these into the context's kwargs.
- **Other overrides:** set `Context.formatter_class` (core.py:340) or subclass and override `make_formatter`.

The `HelpFormatter` docstring (line 118) says the width is "clamped to a maximum of 78". That's the effective result of 80 minus 2, not the `max_width` value itself.
