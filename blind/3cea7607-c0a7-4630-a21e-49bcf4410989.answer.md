**Where the lookup happens** (all in `src/click/core.py`):
- `Parameter.resolve_envvar_value` (L2868–2911) reads the explicit `envvar` from `os.environ`. If `envvar` is a list, it returns the first non-empty value. An empty string counts as unset.
- `Option.resolve_envvar_value` (L3748–3770) calls the base method first. If that finds nothing, and `allow_from_autoenv` is true, `ctx.auto_envvar_prefix` is set and `self.name` is set, it builds the name `f"{ctx.auto_envvar_prefix}_{self.name.upper()}"` (L3764) and looks that up.
- `Option.value_from_envvar` (L3772–3818) post-processes the raw string: it interprets flag values and splits values for `nargs`/`multiple`. `Parameter.value_from_envvar` (L2913) only splits when `nargs != 1`.

**How the prefix is formed** (`Context.__init__`, L506–521): an explicit prefix is uppercased. With no explicit prefix, a subcommand inherits `f"{parent.auto_envvar_prefix}_{self.info_name.upper()}"`. In both cases `-` is then replaced with `_`. For example, prefix `MY-APP`, subcommand `sync` and option `dry_run` give `MY_APP_SYNC_DRY_RUN`. `Option.get_help_extra` (L3626) builds the same name to display it in help.

**Resolution order** (`Parameter.consume_value`, L2680–2726):
1. The command-line value parsed into `opts` (`COMMANDLINE`).
2. Environment, via `value_from_envvar` (`ENVIRONMENT`, L2704–2707).
3. `ctx.lookup_default(self.name)` from the default map (`DEFAULT_MAP`, L2710–2713).
4. `self.get_default(ctx)` (`DEFAULT`, L2720–2724).

So the environment is checked only after the command line, and before both the default map and the default. `Option.consume_value` (L3820) adds a prompt step afterwards. It prompts when the value is still unset or came from the default map or default, provided the option has `prompt` set and is required or `prompt_required`, and parsing isn't resilient.
