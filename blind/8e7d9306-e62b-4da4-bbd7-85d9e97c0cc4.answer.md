The decision is made in one place, `src/click/utils.py` `echo()` at line 330: `elif should_strip_ansi(file, resolve_color_default(color)): out = strip_ansi(out)`. It only applies to `str` output. Empty messages return before this check, and `bytes`/`bytearray` are written untouched to the binary stream when one is found.

**What feeds it**
1. **`color` argument to `echo()`** (`utils.py:245`), which is `True`, `False` or `None`.
2. **`resolve_color_default(color)`** in `src/click/globals.py:54-67`: an explicit `color` is used as-is. If it's `None`, it uses `ctx.color` from the current Context, if there is one. Otherwise it stays `None`.
3. **`Context.color`** (`src/click/core.py:523-527`): set by the `color=` constructor argument, and inherited from the parent context when not given.
4. **The target stream `file`**: the `file=` argument, or `_default_text_stdout()`/`_default_text_stderr()` depending on `err` (`utils.py:288-291`).

**The rule** is in `src/click/_compat.py` `should_strip_ansi(stream, color)` (lines 502-513):
- If `color` is not `None`, strip exactly when `not color`, so an explicit choice always wins.
- If `color` is `None` and the stream has a `color` attribute (the pager's `_PagerWriter`), don't strip, because the pager handles that itself.
- Otherwise, strip when the stream is not a TTY **and** is not Jupyter kernel output. `isatty()` (`_compat.py:540`) calls `stream.isatty()` and treats any exception as False. `_is_jupyter_kernel_output()` (`_compat.py:495`) unwraps click's stream wrappers and checks whether the class's module starts with `ipykernel.`.
- The stripping itself is `strip_ansi()` (`_compat.py:491`), which applies the regex `_ansi_re` (`_compat.py:19`).

**Override in tests:** `CliRunner.isolation()` in `src/click/testing.py:506-523` swaps `should_strip_ansi` in both `utils` and `_compat` for a version that uses the runner's `color` flag (default `False`) instead of the TTY check.
