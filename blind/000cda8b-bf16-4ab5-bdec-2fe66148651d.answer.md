The wrap width is set in `HelpFormatter.__init__` (`src/click/formatting.py:127-142`), and it's stored as `self.width`.

**How it's computed (lines 134-141):**
- `max_width` defaults to 80 when nobody passes one.
- If no explicit `width` is given, it uses the module global `FORCED_WIDTH` (`formatting.py:11`). If that's also `None`, it uses `max(min(shutil.get_terminal_size().columns, max_width) - 2, 50)`.
- So the terminal's column count is capped at `max_width` (80 by default), then 2 is subtracted, giving 78 by default. The floor is 50: a 40-column terminal still gets width 50.
- The docstring (line 118) says "clamped to a maximum of 78", which matches the default result.
- An explicit `width` is used exactly as given. It skips the terminal check, the 80 cap and the 50 floor.

**Where the context feeds in:** `Context.make_formatter` (`src/click/core.py:664-676`) calls `self.formatter_class(width=self.terminal_width, max_width=self.max_content_width)`. The help and usage code gets its formatter through `ctx.make_formatter()` (`core.py:1128`, `1268`).

**Overrides:**
- **Context arguments:** `Context.__init__` accepts `terminal_width` and `max_content_width` (documented at `core.py:265-275`). A context that doesn't set them inherits them from its parent (lines 438-449). If none is set, both are `None`, which means autodetect with a cap of 80.
- **Per command:** pass `context_settings={"terminal_width": ..., "max_content_width": ...}` to the command. `Command.make_context` copies `context_settings` into the `Context(...)` keyword arguments unless the caller already passed them (`core.py:1386-1390`).
- **Formatter class:** set `Context.formatter_class` (`core.py:340`) or override `make_formatter` to use a different formatter.
- **Tests:** `CliRunner.isolation` (`src/click/testing.py:438-439`) sets `FORCED_WIDTH = 80` and restores it at line 593. That gives a fixed width of 80 in tests, unless a context passes its own `terminal_width`.
