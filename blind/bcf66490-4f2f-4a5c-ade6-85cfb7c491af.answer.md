The decision is made while the arguments are parsed, before the group's callback is ever considered.

1. **Default is set in `Group.__init__`** (`src/click/core.py:1785-1789`): if `no_args_is_help` isn't passed, it becomes `not invoke_without_command`. A plain `@click.group()` therefore gets `invoke_without_command=False` and `no_args_is_help=True`.
2. **The check is in `Group.parse_args`** (`core.py:2038-2040`): `if not args and self.no_args_is_help and not ctx.resilient_parsing: raise NoArgsIsHelpError(ctx)`. `Command.make_context` calls it at `core.py:1393`, so this happens before any callback or subcommand runs. `Command.parse_args` has the same check (`core.py:1397`), but there the default is `False`.
3. **The help comes from `NoArgsIsHelpError`** (`src/click/exceptions.py:332-339`): it's a `UsageError` whose message is `ctx.get_help()`, and its `show()` prints that text to stderr. `Command.main` catches it as a `ClickException`, calls `e.show()`, then calls `sys.exit` with exit code 2 (`core.py:1630-1644`).
4. **`Group.invoke` handles the other cases** (`core.py:2058-2064`): it only runs if parsing didn't raise. With no subcommand (`ctx._protected_args` empty):
   - if `invoke_without_command` is set, it runs the group callback via `super().invoke(ctx)`;
   - otherwise it calls `ctx.fail("Missing command.")`.

How the two flags combine:
- **Default** (`invoke_without_command=False`, `no_args_is_help=True`): an empty command line shows help (step 2).
- **`invoke_without_command=True`**: `no_args_is_help` defaults to `False`, so parsing doesn't raise and the callback runs.
- **Both flags `True` explicitly**: help still wins, because the `parse_args` check runs first.
- **`no_args_is_help=False`, `invoke_without_command=False`**: you get "Missing command." instead of help. The same happens when options are given but no subcommand, since `args` isn't empty.
