All of this is in `src/click/core.py`:

1. **Explicit envvar:** `Parameter.resolve_envvar_value` (2868–2911) reads `self.envvar`. If it's a string, it calls `os.environ.get`. If it's a list, it returns the first non-empty value. A variable that is missing or set to an empty string counts as unset (`None`).
2. **Auto envvar:** `Option.resolve_envvar_value` (3748–3770) calls the parent version first. Only if that returns `None`, and `allow_from_autoenv` is true and `ctx.auto_envvar_prefix` is set, does it build `f"{ctx.auto_envvar_prefix}_{self.name.upper()}"` (3764) and look that up. So an explicit `envvar=` wins over the auto name.
3. **Building the prefix:** `Context.__init__` (506–521) upper-cases an explicit prefix. With no explicit prefix, a subcontext inherits `f"{parent.auto_envvar_prefix}_{self.info_name.upper()}"`. Either way, `-` becomes `_`. For example, prefix `MYAPP`, subcommand `sub-cmd` and option `name` give `MYAPP_SUB_CMD_NAME`. The parameter name is upper-cased but its dashes are not replaced; `self.name` is normally already an identifier.
4. **Parsing the raw string:** `Option.value_from_envvar` (3772–3818) turns it into a value. For non-bool flags it matches `flag_value` or reads the string as a boolean. For `nargs != 1` or `multiple` it splits the string with `type.split_envvar_value`.
5. **Resolution order:** `Parameter.consume_value` (2680–2726) works through the sources in this order:
   - command line (`opts`)
   - environment (`value_from_envvar`, 2703–2707, `ParameterSource.ENVIRONMENT`)
   - `ctx.lookup_default` / default map (2709–2713)
   - `get_default` (2720–2724)
6. **Prompt:** `Option.consume_value` (3820ff) then calls the parent, and may prompt if the value is still unset or came from the default map or the default (3865–3869).
