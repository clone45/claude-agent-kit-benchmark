- **Explicit `envvar` lookup:** `src/click/core.py`, `Parameter.resolve_envvar_value` (2868–2911). If `envvar` is a single string, it returns that variable's value. If it is a list, it returns the first variable with a non-empty value. An empty value counts as unset.
- **Auto-prefix lookup:** `Option.resolve_envvar_value` (3748–3770) calls the base method first. Only if that returns nothing, and `allow_from_autoenv` is true, `ctx.auto_envvar_prefix` is set and `self.name` exists, it reads `f"{ctx.auto_envvar_prefix}_{self.name.upper()}"` (3764). So an explicit `envvar` always wins over the auto name.
- **How the prefix is built:** `Context.__init__` (506–521).
  - A prefix you pass in is uppercased.
  - If you pass none, it is inherited as `f"{parent.auto_envvar_prefix}_{self.info_name.upper()}"`, so subcommands nest (e.g. `MYAPP_SUB`).
  - In both cases `-` is then replaced with `_`.
  - Example: option `--user-name` on subcommand `sub` under prefix `myapp` reads `MYAPP_SUB_USER_NAME`. `self.name` is already the underscored identifier.
- **Turning the string into a value:** `Option.value_from_envvar` (3772–3818) handles it. It splits values when `nargs != 1` or `multiple` is set, and parses non-boolean flags via `str_to_bool` / `flag_value`. The base version is `Parameter.value_from_envvar` (2913–2926).
- **Resolution order:** `Parameter.consume_value` (2680–2725) tries each source only while the value is still `UNSET`:
  1. the command line (`opts`), as `COMMANDLINE`
  2. the environment, via `value_from_envvar`, as `ENVIRONMENT` (2703–2707)
  3. the default map, via `ctx.lookup_default`, as `DEFAULT_MAP` (2709–2713)
  4. the default, via `get_default`, as `DEFAULT` (2720–2724)
- **Prompt step:** `Option.consume_value` (3820ff) runs after the base method. It prompts only when the value is still `UNSET` or came from `DEFAULT_MAP`/`DEFAULT`, so a value from the environment suppresses the prompt.
