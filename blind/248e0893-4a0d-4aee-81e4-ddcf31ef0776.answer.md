It's decided while parsing, before the callback ever gets a chance to run:

1. **Default** — `src/click/core.py`, `Group.__init__` (1785–1789): if `no_args_is_help` is left as `None`, it is set to `not invoke_without_command`. So a plain `Group` (where `invoke_without_command=False`) gets `no_args_is_help=True`.
2. **The decision** — `Group.parse_args` (2038–2040): `if not args and self.no_args_is_help and not ctx.resilient_parsing: raise NoArgsIsHelpError(ctx)`. It's reached from `Command.make_context` (1393), so `Group.invoke` and the callback never run.
3. **The help text** — `src/click/exceptions.py`, `NoArgsIsHelpError.__init__` (332–336) uses `ctx.get_help()` as the message. Its `show()` (338–339) prints it to stderr with no "Usage error" framing.
4. **Printing and exit** — `Command.main` (1629–1633) catches it as a `ClickException`, calls `e.show`, and exits with `UsageError.exit_code`, which is 2 (`exceptions.py:77`). If `standalone_mode=False`, it re-raises instead.
5. **The other flag** — `Group.invoke` (2058–2065): with no subcommand, `invoke_without_command=True` runs the group callback (`super().invoke`) and then the result callback. Otherwise it calls `ctx.fail("Missing command.")`.

How the two flags combine:
- **Defaults** (`False`/`None` → `True`): help is printed.
- **`invoke_without_command=True`, `no_args_is_help` left unset** (→ `False`): the callback runs.
- **Both `True`**: help wins, because `parse_args` runs before `invoke`.
- **Both `False`**: you get a "Missing command." usage error.

`Command.parse_args` (1396–1398) has the same check, but for a plain `Command` `no_args_is_help` defaults to `False`.
