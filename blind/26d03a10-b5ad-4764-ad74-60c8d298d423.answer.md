It's decided while the arguments are parsed, before the callback can run. All references are in `src/click/core.py` unless noted.

1. **The default comes from the other flag.** In `Group.__init__` (lines 1785–1789), if `no_args_is_help` is left as `None` it is set to `not invoke_without_command`. A plain `@click.group()` has `invoke_without_command=False`, so it gets `no_args_is_help=True`.
2. **The decision itself.** `Group.parse_args` (lines 2038–2040) checks `if not args and self.no_args_is_help and not ctx.resilient_parsing:` and raises `NoArgsIsHelpError(ctx)`. `Command.parse_args` (lines 1396–1398) has the same check, but the base `Command` defaults to `False`.
3. **Why the callback never runs.** `Command.make_context` (line 1359) calls `self.parse_args(ctx, args)` at line 1393, so the exception is raised before `Group.invoke` is reached.
4. **How the help gets printed.** `NoArgsIsHelpError.__init__` in `src/click/exceptions.py` (line 332) builds its message from `ctx.get_help()`, and its `show()` echoes that text to stderr with no "Error:" prefix. Because it's a `UsageError` (a `ClickException`), `Command.main` catches it at line 1629 and calls `e.show`, which exits with `UsageError`'s code, 2.
5. **When `invoke_without_command=True`.** `no_args_is_help` then defaults to `False`, parsing goes through, and `Group.invoke` (lines 2058–2064) finds no subcommand and runs the group callback via `super().invoke(ctx)`. For a chained group the result callback gets `[]`.
6. **When both are `False`.** If `no_args_is_help=False` is set explicitly and `invoke_without_command` stays `False`, `Group.invoke` reaches `ctx.fail("Missing command.")` at line 2065 and prints a usage error instead of the help.
7. **If both are `True`,** the help check in `parse_args` happens first. A bare invocation shows help, while options with no subcommand still run the callback.
