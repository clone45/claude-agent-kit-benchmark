It's decided while the arguments are parsed, before the group's callback ever runs:

1. **Default coupling:** in `src/click/core.py`, `Group.__init__` (lines 1785–1789) sets `no_args_is_help = not invoke_without_command` when you don't pass `no_args_is_help`. A plain group has `invoke_without_command=False`, so it gets `no_args_is_help=True`.
2. **The decision:** `Group.parse_args` (line 2038, check at 2039–2040) raises `NoArgsIsHelpError(ctx)` when `not args and self.no_args_is_help and not ctx.resilient_parsing`. This runs from `Command.make_context` (line 1393), before `invoke`, so the callback never runs.
3. **Printing:** in `src/click/exceptions.py`, `NoArgsIsHelpError.__init__` (lines 332–339) uses `ctx.get_help()` as its message, and `show()` echoes it to stderr. `Command.main` catches it as a `ClickException` (core.py ~1629) and in standalone mode calls `e.show` and exits with the `UsageError` code (2).
4. **How the two flags combine** (once parsing gets past the check), in `Group.invoke` (line 2052, branch at 2058–2063). With no subcommand (`not ctx._protected_args`):
   - if `invoke_without_command` is set, the callback runs (`super().invoke`) and the result callback gets its return value, or `[]` for chained groups;
   - otherwise it calls `ctx.fail("Missing command.")`.
5. **Result:**
   - Defaults: help is shown.
   - `invoke_without_command=True`: the callback runs.
   - `invoke_without_command=True, no_args_is_help=True`: help still wins, because `parse_args` runs first.
   - `no_args_is_help=False` without `invoke_without_command`: you get the "Missing command." error instead of help.
   - This only applies to a truly empty argv. Options with no subcommand skip the help check and reach step 4.
6. **Plain commands:** `Command.parse_args` (lines 1396–1398) has the same check, but there `no_args_is_help` defaults to `False`.
