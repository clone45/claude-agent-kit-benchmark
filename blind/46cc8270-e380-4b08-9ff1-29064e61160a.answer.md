The decision happens at parse time, before any callback runs.

1. **Defaults**: `src/click/core.py`, `Group.__init__` (l.1785–1789). If you don't pass `no_args_is_help`, it is set to `not invoke_without_command`. A plain `@click.group()` has `invoke_without_command=False`, so it gets `no_args_is_help=True`.
2. **The check**: `Group.parse_args` (l.2038–2040) runs `if not args and self.no_args_is_help and not ctx.resilient_parsing: raise NoArgsIsHelpError(ctx)`. It is called from `Command.make_context` (l.1393), so the callback never gets a chance to run. `Command.parse_args` (l.1396–1398) has the same check for plain commands, but there `no_args_is_help` defaults to False.
3. **The help text**: `src/click/exceptions.py`, `NoArgsIsHelpError.__init__` (l.335–336) uses `ctx.get_help()` as the error message. Its `show()` (l.338–339) prints that message to stderr without the usual "Error:" prefix.
4. **Printing and exit**: `Command.main` (core.py l.1629–1633) catches it as a `ClickException`, calls `e.show()` and exits with code 2, inherited from `UsageError`. With `standalone_mode=False` the exception is re-raised instead.
5. **How the two flags combine**: `Group.invoke` (l.2058–2066) only runs if parsing succeeded. When there is no subcommand, it runs the group callback if `invoke_without_command=True`, and otherwise fails with "Missing command."
   - `invoke_without_command=False` (default): `no_args_is_help` becomes True, so bare `cli` prints help. If you set `no_args_is_help=False` explicitly, you get "Missing command." instead.
   - `invoke_without_command=True`: `no_args_is_help` becomes False, so bare `cli` runs the callback. If you set both to True, help wins with zero args, because `parse_args` raises before `invoke` is reached. With only options given (e.g. `cli --flag`), the callback runs.
