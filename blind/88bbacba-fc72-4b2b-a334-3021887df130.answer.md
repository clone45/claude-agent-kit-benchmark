The decision happens in one place: `src/click/utils.py`, `echo()`, lines 328–331. That branch only runs when the message is a `str`. Bytes go to the binary stream untouched (lines 320–326), and empty output just gets a flush.

**What feeds it:**
1. **The `color` argument to `echo()`.** It goes through `resolve_color_default()` in `src/click/globals.py:54`. If `color` is not `None`, it is returned as is. Otherwise the function returns `ctx.color` from the current Context, or `None` when there is no context.
2. **Context color.** It is set in `Context.__init__` (`src/click/core.py:523–527`). If `color` isn't given, the context inherits `parent.color`.

**The rule:** `should_strip_ansi(stream, color)` in `src/click/_compat.py:502–514` decides.
- If `color` is set, it returns `not color`. `True` keeps the codes and `False` strips them, whatever the stream is.
- If `color` is `None`, it looks at the stream:
  - A stream of `None` falls back to `sys.stdin`.
  - A stream with a `color` attribute (the pager's `_PagerWriter`, which handles stripping itself) returns `False`, so nothing is stripped.
  - Otherwise it strips unless the stream is a TTY or is Jupyter kernel output.
- The TTY check is `isatty()` (`_compat.py:540`): it calls `stream.isatty()`, and any exception counts as "not a TTY".
- The Jupyter check is `_is_jupyter_kernel_output()` (`_compat.py:495`). It unwraps `_FixupStream` and `_NonClosingTextIOWrapper`, then tests whether the stream class's module starts with `ipykernel.`.

**The stripping:** `strip_ansi()` (`_compat.py:491`) removes the codes with the `_ansi_re` regex.

In short, an explicit `color` (from the call, or else inherited through the Context chain) wins. Without one, codes are kept only for a TTY, a Jupyter kernel, or the pager writer.
