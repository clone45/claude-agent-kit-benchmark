The wrap width is decided in **`HelpFormatter.__init__`** (`src/click/formatting.py:128-142`):

- **Default cap:** if `max_width` is `None`, it is set to `80` (line 135).
- **Terminal size:** if `width` is `None`, it uses the module global `FORCED_WIDTH` (line 11). If that is also `None`, it computes `max(min(shutil.get_terminal_size().columns, max_width) - 2, 50)` (line 141).
- **Result:** the width is the terminal width capped at 80, minus 2. So it is **78 at most by default** (the docstring at line 118 says "clamped to a maximum of 78") and **never less than 50**.
- **The floor only applies to auto-detection:** an explicit `width` is used exactly as given, with no clamping.
- **Tests:** `CliRunner.isolation` (`src/click/testing.py:438-439`, restored at 593) sets `formatting.FORCED_WIDTH = 80` while it runs, so test output doesn't depend on the real terminal.

How it gets wired up and overridden:
- **`Context.__init__`** (`src/click/core.py:438-449`) takes `terminal_width` and `max_content_width`. Each one is inherited from the parent context when it isn't given.
- **`Context.make_formatter`** (`core.py:664-676`) passes them on as `formatter_class(width=self.terminal_width, max_width=self.max_content_width)`.
  - `terminal_width` replaces auto-detection entirely.
  - `max_content_width` raises or lowers the 80 cap (the 50 floor still applies).
- **`Command.get_help`** (`core.py:1263-1270`) calls `ctx.make_formatter()`.
- **Per-command override:** pass `context_settings={"terminal_width": ..., "max_content_width": ...}` to a command. `Command.make_context` (`core.py:1386-1388`) merges these into the new `Context` unless the caller already passed them as keyword arguments.
- **Further hooks:** set `Context.formatter_class` (`core.py:340`) to your own formatter, or subclass `Context` and override `make_formatter`.
