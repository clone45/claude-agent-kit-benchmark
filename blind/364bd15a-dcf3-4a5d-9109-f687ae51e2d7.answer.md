The wrap width is decided in **`HelpFormatter.__init__`** in `src/click/formatting.py:127-142`:

- **Default:** `max_width` is 80 when not given (lines 134-135). The docstring at line 118 says the default is "clamped to a maximum of 78", which doesn't match the code.
- **Terminal size and minimum:** if no explicit `width` is passed, it uses `width = max(min(shutil.get_terminal_size().columns, max_width) - 2, 50)` (line 141). So the width is the terminal's column count capped at `max_width`, minus 2, and never less than **50**. On a wide terminal you get 78; on a narrow one you still get 50. An explicit `width` skips all of this, including the 50 floor.
- **Forced width:** before checking the terminal, it reads the module global `FORCED_WIDTH` (`formatting.py:11`, used at line 139). `CliRunner.isolation` in `src/click/testing.py:438-439` sets it to 80 so test output doesn't depend on the terminal, and restores it at line 593.
- **Context override:** `Context.__init__` (`src/click/core.py:378-379, 438-449`) takes `terminal_width` and `max_content_width`. Each one is inherited from the parent context if not set.
- **How they reach the formatter:** `Context.make_formatter` (`core.py:664-675`) builds `self.formatter_class(width=self.terminal_width, max_width=self.max_content_width)`. Setting `terminal_width` fixes the width outright; setting `max_content_width` only changes the 80 cap.
