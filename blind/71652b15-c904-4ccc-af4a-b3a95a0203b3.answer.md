- **Lookup code:** `Option.resolve_envvar_value` (`src/click/core.py:3748-3770`) first calls `Parameter.resolve_envvar_value` (`core.py:2868-2911`). That checks the explicit `envvar` (one string, or a list where the first non-empty one wins) using `os.environ.get`. Empty strings count as unset.
- **Auto-envvar fallback:** If nothing was found, `allow_from_autoenv` is true, `ctx.auto_envvar_prefix` is set and the option has a `name`, it looks up `f"{ctx.auto_envvar_prefix}_{self.name.upper()}"` (`core.py:3763-3764`). So `--max-count` (name `max_count`) with prefix `MYAPP` becomes `MYAPP_MAX_COUNT`.
- **How the prefix is built:** In `Context.__init__` (`core.py:503-521`), an explicit prefix is uppercased. With no explicit prefix, a subcommand inherits `f"{parent.auto_envvar_prefix}_{self.info_name.upper()}"`, so a `run` subcommand gets `MYAPP_RUN`. Every `-` is then replaced with `_`.
- **Turning the string into a value:** `Option.value_from_envvar` (`core.py:3772+`) handles non-bool flags and `multiple`. `Parameter.value_from_envvar` (`core.py:2913-2926`) splits the string with `type.split_envvar_value` when `nargs != 1`.
- **Resolution order:** `Parameter.consume_value` (`core.py:2680-2726`) tries each source in turn and stops at the first one that gives a value:
  1. Command line: `opts.get(self.name)` → `COMMANDLINE`
  2. Environment: `value_from_envvar` → `ENVIRONMENT` (`2703-2707`)
  3. Default map: `ctx.lookup_default` → `DEFAULT_MAP` (`2709-2717`)
  4. Default: `get_default` → `DEFAULT` (`2719-2724`)
- **Prompt:** `Option.consume_value` (`core.py:3820-3875`) then may prompt, but only when the value is still unset or came from the default map or default (`source >= DEFAULT_MAP`). That makes the prompt last in line, after the environment.
