All of this lives in `src/click/core.py`:

- **Reading the variable:** `Parameter.resolve_envvar_value` (2868–2911) checks the explicit `envvar` (a string or a list) and returns the first non-empty value. `Option.resolve_envvar_value` (3748–3770) calls that first. If it finds nothing and `allow_from_autoenv` is true, `ctx.auto_envvar_prefix` is set and the option has a `name`, it looks up `f"{ctx.auto_envvar_prefix}_{self.name.upper()}"` (3763–3767). An empty string counts as not set.
- **Post-processing:** `Parameter.value_from_envvar` (2913–2926) splits the string when `nargs != 1`. `Option.value_from_envvar` (3772+) also interprets values for non-boolean flags and handles `multiple`.
- **How the prefix is built:** `Context.__init__` (503–521). An explicit prefix is uppercased. Without one, a subcommand inherits `f"{parent.auto_envvar_prefix}_{self.info_name.upper()}"`. In both cases `-` becomes `_`. For example, prefix `MYAPP`, subcommand `sub-cmd` and option `name="user"` give `MYAPP_SUB_CMD_USER`.
- **Resolution order:** `Parameter.consume_value` (2680–2726) tries each source only while the value is still `UNSET`:
  1. command line (`opts`) → `COMMANDLINE`
  2. environment (`value_from_envvar`) → `ENVIRONMENT` (2703–2707)
  3. `ctx.lookup_default` / default map → `DEFAULT_MAP`
  4. `get_default` → `DEFAULT`

  So the environment sits after command-line arguments and before both the default map and the default. `Option.consume_value` (3820+) then resolves flag sentinels and may prompt, but only when the value is `UNSET` or came from the default map or default, not when it came from the environment.
