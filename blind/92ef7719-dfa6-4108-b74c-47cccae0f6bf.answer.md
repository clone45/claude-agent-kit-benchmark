Click decides this in `echo` itself, by calling `should_strip_ansi(file, resolve_color_default(color))`.

- **Where it's decided:** `src/click/utils.py`, `echo`, lines 330–331. If that call returns True, the text goes through `strip_ansi` (`_compat.py:491`, a regex substitution) before `file.write`. Bytes output returns early at line 326 and is never stripped.
- **Input 1, the color flag:** `src/click/globals.py`, `resolve_color_default` (54–67). An explicit `color=` argument to `echo` wins. Otherwise it uses the current `Context.color`, which a child context inherits from its parent (`core.py:522–526`). With no context, it's `None`.
- **Input 2, the stream:** `src/click/_compat.py`, `should_strip_ansi` (502–513), applies the rule:
  - `color` is True: keep the codes. `color` is False: strip them.
  - `color` is None: auto-detect from the stream. A missing stream is treated as `sys.stdin`. A stream with a `color` attribute (the pager writer, which strips on its own) is never stripped. Anything else is stripped unless it's a TTY or a Jupyter kernel stream.
- **TTY check:** `_compat.py`, `isatty` (540–544), calls `stream.isatty()` and treats any exception as "not a TTY".
- **Jupyter check:** `_compat.py`, `_is_jupyter_kernel_output` (495–499), unwraps `_FixupStream` and `_NonClosingTextIOWrapper`, then checks whether the stream's class module starts with `ipykernel.`.
- **Test override:** `src/click/testing.py`, `CliRunner.isolation` (504–523), temporarily swaps in its own `should_strip_ansi` on `utils` and `_compat`. When `color` is None it uses the runner's `color` setting (default False, so output is stripped), and restores the originals afterwards (591–592).
- **Same rule elsewhere:** `termui.py:99` uses the same check by looking up `_compat.should_strip_ansi` on the module, so the test override reaches it too.

In short, an explicit color setting (from the argument or the context chain) always wins. Otherwise codes are stripped unless the output is a terminal, a Jupyter kernel or click's pager.
